## Rules

- All comments and variable names must be in **English**.
- **Never run `composer install`, `composer update`, `composer dump-autoload`, or any build command.** The developer handles all dependency and autoload management manually.
- Never uninstall the module (it would unregister its hooks): disable it only.

## Project overview

`awgeodisorderlink` is a PrestaShop 9 module (9.0+ only, since v2.0.0; last PS 8 release tagged `v1.0.0`) that links the admin order page to the Geodis shipment of the order (module `geodisofficiel`, legacy admin controller `AdminGeodisShipment`), and sets the order status to "Shipped" (`PS_OS_SHIPPING`).

No database table, no configuration key, no configuration page, no menu tab.

## Architecture

### Module entry point

`awgeodisorderlink.php` — `AwGeodisOrderLink extends Module`. Hooks (both back office only, wrapped in `try/catch (Throwable)` + `PrestaShopLogger::addLog()`):

- `hookDisplayAdminOrderMain(array $params): string` — renders `views/templates/admin/awgeodisorderlink.html.twig` (via `$this->getTwig()`) only when the order carrier has `external_module_name = 'geodisofficiel'`. Variables: `geodis_url`, `logo_url`, `order_id` (on the button, `data-order-id`).
- `hookActionAdminControllerSetMedia(): void` — on `AdminOrders` and `AdminGeodisShipment` only (`Tools::getValue('controller')`, also set on the Symfony order page). Adds the JS def `awGeodisOrderLinkUpdateStateOrderAjaxControllerUri` (route generated with `$this->get('router')`) and the page script. On `AdminGeodisShipment`, also `awGeodisOrderLinkOrderId` (from the `id_order` query parameter).

The hooks only use core services (twig, router) and always run in the back office: no `getService()` fallback and no front container are needed. If a hook ever needs a module service, follow the `getService()` pattern of awfaq/awaffiliate (same public ids in `config/admin/services.yml` and `config/front/services.yml`).

### AJAX endpoint

| File | Role |
|---|---|
| `config/routes.yml` | `axelweb_awgeodisorderlink_ajax_update_state_order`: POST `/modules/awgeodisorderlink/ajax-update-state-order`, `_legacy_controller: AdminOrders` |
| `src/Controller/AwGeodisOrderLinkController.php` | `ajaxUpdateStateOrder()`: JSON body `{"orderId": 123}` |
| `config/admin/services.yml` | Controller service, autowired (id = class name) |

Responses: `{"success": bool, "message": string}` — 400 missing id, 404 unknown order, 500 on failure (logged), 200 on success. Access: `#[AdminSecurity("is_granted('update', ...)", jsonResponse: true)]` → 403 JSON `{"status": false, "message": ...}`. The admin `_token` is required in the URL (generated by the router).

The status is only added if the order is not already in `PS_OS_SHIPPING`. `OrderHistory::add()` (no customer email). The output buffer is cleaned before the JSON response (other modules' order status hooks may echo).

### Front-end scripts

| File | Role |
|---|---|
| `views/js/awgeodisorderlink.js` | Order page: `fetch` POST on `#geodis-link-update-status` click, order id from `data-order-id`, `showSuccessMessage` / `showErrorMessage` |
| `views/js/awgeodisshipment.js` | Geodis shipment page: stores `awGeodisOrderLinkOrderId` in `sessionStorage`, sends `navigator.sendBeacon` on `.js-transmit` click (a `fetch` would be cancelled by the form submission) |

### PrestaShop 9 conventions

- Controllers extend `PrestaShopAdminController`, dependencies are injected in the constructor (no `$this->get()`), permissions use the `#[AdminSecurity]` attribute, `trans($id, [], 'Domain')`.
- PSR-4: `Axelweb\AwGeodisOrderLink\` → `src/`.
- The translation domain must be a **string literal** in each `trans()` call (Twig: `trans_default_domain` is fine), otherwise the extractor misses it.
